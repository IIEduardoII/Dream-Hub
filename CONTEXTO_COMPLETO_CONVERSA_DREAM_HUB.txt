1. SUMÁRIO EXECUTIVO E VISÃO GERAL DO SISTEMA
================================================================================

O Dream-Hub é uma plataforma unificada de produtividade e gestão pessoal baseada
na filosofia Local-First e Personal Cloud Edge. O sistema centraliza quatro
pilares operacionais vitais:
  1. Gestão de Tempo (Sessões de Foco e Pomodoro nativo)
  2. Gestão de Atividades (Tarefas, Projetos e Recorrências)
  3. Gestão Financeira (Receitas, Despesas e Fluxo de Caixa Mensal)
  4. Incubadora de Ideias (Brain Dump, Notas Rápidas e Conversão em Ações)

Diferente de soluções convencionais de terceiros (como Notion, Todoist ou Mobills),
o Dream-Hub opera de maneira soberana diretamente no hardware do próprio usuário:
um smartphone Android executando Termux, orquestrado com Nginx, Gunicorn e
SQLite 3 com Write-Ahead Logging (WAL). O acesso remoto é privado e criptografado
ponto a ponto via malha Tailscale (WireGuard), sem exposição à internet pública.

---
[FILOSOFIA DE SOBERANIA E EDGE COMPUTING]
A premissa fundamental do Dream-Hub é a soberania absoluta dos dados e o custo
zero de infraestrutura na nuvem: o smartphone que o usuário já carrega no bolso
atua como servidor 24/7 de alta confiabilidade, dispensando assinaturas, evitando
telemetria invasiva e viabilizando latências de resposta em milissegundos na rede
local/VPN.

1.1 DIAGNÓSTICO CRÍTICO: O QUE COSTUMA FALTAR EM SISTEMAS GERADOS POR IA?
--------------------------------------------------------------------------------
O código inicial do Dream-Hub foi concebido com apoio de agentes autônomos de IA.
Embora modelos de IA sejam eficientes para gerar rotas básicas de CRUD, eles
sistematicamente incorrem em vícios arquiteturais que justificam esta refatoração:

1. Fragmentação Funcional em Silos Isolados:
   Agentes de IA tendem a criar quatro telas independentes que não dialogam. Na
   prática, uma ideia anotada deve virar uma tarefa com 1 clique; uma sessão de
   Pomodoro deve acumular tempo diretamente em uma tarefa ativa; e uma tarefa
   ou projeto precisa poder apontar custos financeiros atrelados.

2. Ausência de Cockpit Unificado ("Meu Dia"):
   Falta uma tela agregadora inicial. O usuário não deve ter que navegar por 4
   módulos diferentes para entender seu dia. Ele precisa de resposta em 3 segundos:
   - "Quais tarefas vencem hoje?"
   - "Quanto tempo foquei hoje?"
   - "Qual o meu saldo disponível do mês?"
   - Um botão universal de anotação rápida.

3. Atrito na Captura Rápida (Zero-Friction Quick Capture):
   Anotar uma ideia na rua ou lançar uma despesa rápida de café precisa de no
   máximo 2 toques. Exigir navegação profunda causa fadiga cognitiva e leva ao
   abandono do sistema.

4. Negligência com o Ciclo de Vida do Sistema Operacional Móvel:
   O Android possui mecanismos agressivos de economia de bateria (OOM Killer, CPU
   sleep, descarte de processos em segundo plano). Aplicações comuns ignoram o
   wake-lock permanente, a supervisão de daemons com Runit e a configuração de
   checkpoints do SQLite WAL, causando instabilidade e corrupção silenciosa.

5.Adicionar um gasto recorrente/depósito, invés de precisa adicionar todo gasto ou depósito manualmente poder adicionar um recorrente

2.1 TOPOLOGIA DE REDE E CAMADA DE SEGURANÇA (TAILSCALE)
--------------------------------------------------------------------------------
- Criptografia Ponto a Ponto: O celular e os dispositivos autorizados operam
  na malha privada (Tailnet) sob a faixa 100.64.0.0/10.
- Bloqueio de Portas Públicas: O Nginx não escuta na internet aberta e não requer
  redirecionamento de portas no roteador (UPnP). O acesso externo via Wi-Fi público
  ou rede móvel recebe resposta HTTP 403 Forbidden.

2.2 OTIMIZAÇÕES SQLITE PARA CONCORRÊNCIA NO ANDROID
--------------------------------------------------------------------------------
Toda conexão SQLite deve inicializar com os seguintes parâmetros para evitar
erros de "database is locked":

  PRAGMA journal_mode = WAL;         -- Leituras não bloqueiam escritas
  PRAGMA synchronous = NORMAL;       -- Balanço ideal entre velocidade e integridade
  PRAGMA foreign_keys = ON;          -- Integridade referencial obrigatória
  PRAGMA temp_store = MEMORY;        -- Tabelas temporárias em RAM
  PRAGMA cache_size = -8000;         -- 8MB de cache alocado em RAM
  PRAGMA busy_timeout = 5000;        -- Espera até 5s por liberação de trava

4. MODELAGEM DE DADOS RELACIONAL (DDL SQLITE WAL)

-- Categorias unificadas para Tarefas e Finanças
CREATE TABLE IF NOT EXISTS categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    color TEXT DEFAULT '#2563EB',
    icon TEXT DEFAULT 'folder',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Atividades e Tarefas
CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT,
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    priority TEXT CHECK(priority IN ('baixa', 'media', 'alta')) DEFAULT 'media',
    status TEXT CHECK(status IN ('pendente', 'em_progresso', 'concluida')) DEFAULT 'pendente',
    due_date DATE,
    recurrence TEXT CHECK(recurrence IN ('nenhuma', 'diaria', 'semanal', 'mensal')) DEFAULT 'nenhuma',
    estimated_pomodoros INTEGER DEFAULT 1,
    completed_pomodoros INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    completed_at DATETIME
);

-- Sessões de Tempo e Foco (Pomodoro)
CREATE TABLE IF NOT EXISTS time_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER REFERENCES tasks(id) ON DELETE SET NULL,
    type TEXT CHECK(type IN ('pomodoro', 'short_break', 'long_break')) NOT NULL,
    duration_minutes INTEGER NOT NULL,
    notes TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Gestão Financeira (Transações)
CREATE TABLE IF NOT EXISTS transactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    type TEXT CHECK(type IN ('receita', 'despesa')) NOT NULL,
    amount DECIMAL(10,2) NOT NULL,
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    task_id INTEGER REFERENCES tasks(id) ON DELETE SET NULL,
    description TEXT NOT NULL,
    transaction_date DATE NOT NULL,
    is_recurring BOOLEAN DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Incubadora de Ideias
CREATE TABLE IF NOT EXISTS ideas (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    content TEXT,
    tags TEXT,
    status TEXT CHECK(status IN ('bruta', 'em_analise', 'convertida', 'arquivada')) DEFAULT 'bruta',
    converted_task_id INTEGER REFERENCES tasks(id) ON DELETE SET NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Índices de Performance
CREATE INDEX IF NOT EXISTS idx_tasks_due_status ON tasks(due_date, status);
CREATE INDEX IF NOT EXISTS idx_transactions_date ON transactions(transaction_date);
CREATE INDEX IF NOT EXISTS idx_time_sessions_created ON time_sessions(created_at);
CREATE INDEX IF NOT EXISTS idx_ideas_status ON ideas(status);

#!/data/data/com.termux/files/usr/bin/sh

mkdir -p "$BACKUP_DIR"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")

# Backup consistente a quente nativo do SQLite (seguro em modo WAL)

find "$BACKUP_DIR" -name "dreamhub_*.db" -type f -mtime +30 -delete
echo "[OK] Backup gerado com sucesso em: $TARGET"

O **Pomodoro** (Técnica Pomodoro) é um método de gestão de tempo criado para manter o foco máximo sem cansar a mente. O nome vem daqueles cronômetros de cozinha em formato de tomate (*pomodoro*, em italiano).

### Como funciona o método?
Em vez de tentar trabalhar ou estudar por várias horas seguidas (o que gera distração e fadiga), você divide o seu tempo em **blocos de concentração total** intercalados com **pausas curtas**:

1. **1 Bloco de Foco (1 Pomodoro🍅)**: Tradicionalmente dura **25 minutos** de concentração total em uma única tarefa (sem olhar redes sociais ou notificações).
2. **Pausa Curta**: Quando o cronômetro zera, você descansa **5 minutos** (levantar, beber água, alongar).
3. **Pausa Longa**: Após completar 4 blocos de foco, você faz uma pausa maior de **15 minutos**.

---

### Como o Pomodoro funciona dentro do seu Dream Hub?

No **Dream Hub**, o Pomodoro não é apenas um relógio solto — ele está integrado às suas **Tarefas** e ao seu **Cockpit ("Meu Dia")**:

1. **Meta de Blocos por Tarefa (`🍅 0/2 • 45m`)**:
   - Quando você cria uma tarefa (ex: *"Estudo IA"*), você pode estimar quantos blocos de foco vai precisar (`Qtd. Pomodoros`) e quantos minutos dura cada bloco naquela tarefa (`15m`, `25m`, `45m`, `50m`, `60m` ou qualquer valor personalizado).
2. **Botão `⏱ Focar` em 1 Clique**:
   - Ao clicar em **`⏱ Focar`** em qualquer tarefa, o Dream Hub já abre a aba **Tempo**, seleciona aquela tarefa automaticamente e ajusta o relógio para a duração que você definiu nela (por exemplo, `45:00`).
3. **Contagem automática de tempo estudado/trabalhado**:
   - Quando o cronômetro chega a `00:00`, o sistema toca um aviso sonoro suave, soma **+1 Pomodoro concluído (`🍅`)** naquela tarefa e adiciona esses minutos no indicador **"Foco Hoje"** da sua tela inicial.
4. **Funciona mesmo com a tela do celular apagada**:
   - Na versão `1.1`, o cronômetro calcula o tempo pelo horário real do sistema, então você pode iniciar o foco, bloquear a tela do celular e, quando voltar, o tempo estará exato.

O Dream-Hub v1.2 eleva a plataforma de um gestor de rotinas diárias para um
sistema consolidado de planejamento tático, gestão do conhecimento pessoal e
previsibilidade financeira.

Esta versão atende a quatro necessidades operacionais centrais:

-- 1. TABELA POLIMÓRFICA DE ANEXOS (Filesystem + Metadados)
CREATE TABLE IF NOT EXISTS attachments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    filename TEXT NOT NULL,          -- Nome original do arquivo (ex: boleto.pdf)
    storage_path TEXT NOT NULL,      -- Caminho relativo no disco (uploads/uuid.ext)
    file_size INTEGER NOT NULL,      -- Tamanho exato em bytes
    mime_type TEXT NOT NULL,         -- Ex: 'application/pdf', 'image/webp'
    entity_type TEXT CHECK(entity_type IN ('task', 'note', 'idea', 'transaction')) NOT NULL,
    entity_id INTEGER NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_attachments_entity ON attachments(entity_type, entity_id);

-- 2. MÓDULO TRANSVERSAL DE METAS (GOALS)
CREATE TABLE IF NOT EXISTS goals (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT,
    category TEXT CHECK(category IN ('financas', 'estudos', 'atividades', 'pessoal')) NOT NULL,
    goal_type TEXT CHECK(goal_type IN ('monetaria', 'quantitativa', 'qualitativa')) NOT NULL,
    target_value DECIMAL(10,2),      -- Ex: R$ 5000.00 ou 50 pomodoros (NULL para qualitativa)
    current_value DECIMAL(10,2) DEFAULT 0.00,
    unit TEXT DEFAULT 'R$',          -- 'R$', 'pomodoros', 'tarefas', 'capítulos'
    deadline DATE,                   -- Opcional
    status TEXT CHECK(status IN ('em_andamento', 'alcancada', 'pausada')) DEFAULT 'em_andamento',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    completed_at DATETIME
);

CREATE INDEX IF NOT EXISTS idx_goals_status ON goals(status);

-- 3. MODO ANOTAÇÕES (KNOWLEDGE BASE PERENE)
CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    content TEXT NOT NULL,           -- Texto estruturado em Markdown
    folder TEXT DEFAULT 'Geral',     -- Agrupador / Caderno
    tags TEXT,                       -- Tags separadas por vírgula
    is_pinned BOOLEAN DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_notes_folder ON notes(folder);
CREATE INDEX IF NOT EXISTS idx_notes_pinned ON notes(is_pinned);

-- 4. CONTRATOS E REGRAS DE TRANSAÇÕES RECORRENTES (FINANÇAS)
CREATE TABLE IF NOT EXISTS recurring_rules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    type TEXT CHECK(type IN ('receita', 'despesa')) NOT NULL,
    description TEXT NOT NULL,
    amount DECIMAL(10,2) NOT NULL,
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    frequency TEXT CHECK(frequency IN ('semanal', 'mensal', 'anual')) DEFAULT 'mensal',
    day_of_month INTEGER CHECK(day_of_month BETWEEN 1 AND 31),
    start_date DATE NOT NULL,
    end_date DATE,                   -- NULL se for indeterminada
    is_active BOOLEAN DEFAULT 1,
    last_generated_date DATE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_recurring_active ON recurring_rules(is_active);

```python
import os
import uuid
from werkzeug.utils import secure_filename
from flask import current_app

UPLOAD_DIR = os.path.expanduser("~/Dream-Hub/uploads")
os.makedirs(UPLOAD_DIR, exist_ok=True)
MAX_FILE_SIZE = 15 * 1024 * 1024 # 15 MB

def save_attachment(file_storage, entity_type, entity_id):
    filename = secure_filename(file_storage.filename)
    ext = os.path.splitext(filename)[1].lower()
    unique_name = f"{uuid.uuid4().hex}{ext}"
    physical_path = os.path.join(UPLOAD_DIR, unique_name)
    
    file_storage.save(physical_path)
    file_size = os.path.getsize(physical_path)
    
    # Grava metadados no SQLite
    with get_db() as db:
        cursor = db.execute(
            """INSERT INTO attachments (filename, storage_path, file_size, mime_type, entity_type, entity_id)
               VALUES (?, ?, ?, ?, ?, ?)""",
            (filename, unique_name, file_size, file_storage.mimetype, entity_type, entity_id)
        )
        db.commit()
        return cursor.lastrowid

def delete_attachment(attachment_id):
    with get_db() as db:
        row = db.execute("SELECT storage_path FROM attachments WHERE id = ?", (attachment_id,)).fetchone()
        if row:
            physical_path = os.path.join(UPLOAD_DIR, row['storage_path'])
            if os.path.exists(physical_path):
                os.remove(physical_path)
            db.execute("DELETE FROM attachments WHERE id = ?", (attachment_id,))
            db.commit()
```

### Etapa 2: Adaptar o `frontend/js/app.js` para Roteamento Híbrido (Web + APK)
No topo absoluto do arquivo `frontend/js/app.js` (antes de qualquer função), adicione o interceptador transparente. Ele mantém o funcionamento idêntico no navegador e redireciona todas as chamadas `/api/...` para `http://100.107.212.104:8090` quando executado dentro do APK:

```javascript
// === CONFIGURAÇÃO HÍBRIDA: WEB BROWSER + ANDROID APK (CAPACITOR) ===
const DEFAULT_TAILSCALE_SERVER = 'http://100.107.212.104:8090';
const IS_NATIVE_APK = Boolean(window.Capacitor) || 
    (window.location.hostname === 'localhost' && (!window.location.port || window.location.port === '80'));

const API_ORIGIN = IS_NATIVE_APK 
    ? (localStorage.getItem('dream_api_origin') || DEFAULT_TAILSCALE_SERVER).replace(/\/+$/, '')
    : '';

// Intercepta window.fetch automaticamente para prefixar chamadas /api/
const _originalFetch = window.fetch.bind(window);
window.fetch = function(input, init) {
    if (typeof input === 'string' && input.startsWith('/api/')) {
        input = `${API_ORIGIN}${input}`;
    }
    return _originalFetch(input, init);
};

// Função utilitária para links de download/anexos (<a href="/api/...">)
window.resolveApiUrl = function(path) {
    if (!path) return '';
    if (path.startsWith('/api/')) return `${API_ORIGIN}${path}`;
    return path;
};

// Reescreve cliques em links <a href="/api/..."> dentro do APK para abrir com a URL completa
document.addEventListener('click', (e) => {
    const link = e.target.closest('a[href^="/api/"]');
    if (link && API_ORIGIN) {
        link.href = `${API_ORIGIN}${link.getAttribute('href')}`;
    }
}, true);
```

E no registro do Service Worker (no `index.html` ou `app.js`), envolva com `if (!IS_NATIVE_APK)` para que o APK use sempre seus próprios arquivos internos instantâneos.

## 6. Passo 4: Script Automatizado de Emissão e Renovação (`scripts/setup-https-duckdns.sh`)

Crie o script `scripts/setup-https-duckdns.sh` no seu projeto. Ele conecta via SSH no **Redmi A3** (`100.107.212.104:8022`), instala o `acme.sh` dentro do Termux, emite o certificado oficial via `DNS-01`, instala em `~/nexus-termux/certs/` e reinicia o `nexus-nginx`:

```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"

if [ ! -f "$PROJECT_ROOT/.env" ]; then
    echo "[ERRO] Arquivo .env nao encontrado em $PROJECT_ROOT/.env"
    exit 1
fi

source "$PROJECT_ROOT/.env"

if [ -z "${DUCKDNS_DOMAIN:-}" ] || [ -z "${DUCKDNS_TOKEN:-}" ]; then
    echo "[ERRO] Defina DUCKDNS_DOMAIN e DUCKDNS_TOKEN no arquivo .env"
    exit 1
fi

SUBDOMAIN="${DUCKDNS_DOMAIN%.duckdns.org}"

echo "==> [1/4] Atualizando IP Tailscale ($TERMUX_HOST) no DuckDNS para $SUBDOMAIN..."
DUCK_RESP=$(curl -fsSL "https://www.duckdns.org/update?domains=${SUBDOMAIN}&token=${DUCKDNS_TOKEN}&ip=${TERMUX_HOST}")
if [ "$DUCK_RESP" != "OK" ]; then
    echo "[ERRO] Falha ao atualizar DuckDNS. Resposta: $DUCK_RESP"
    exit 1
fi
echo "    [OK] DuckDNS apontado para $TERMUX_HOST"

echo "==> [2/4] Conectando ao Redmi A3 via SSH para instalar acme.sh e emitir certificado Let's Encrypt..."
sshpass -p "$TERMUX_PASS" ssh -o StrictHostKeyChecking=no -p "$TERMUX_PORT" "${TERMUX_USER}@${TERMUX_HOST}"     "DUCKDNS_DOMAIN='$DUCKDNS_DOMAIN' DUCKDNS_TOKEN='$DUCKDNS_TOKEN' bash -s" << 'REMOTE_EOF'
set -euo pipefail

# Garante dependencias basicas no Termux
pkg install -y curl openssl-tool cronie >/dev/null 2>&1 || true

# Instala acme.sh se ainda nao estiver instalado
if [ ! -f "$HOME/.acme.sh/acme.sh" ]; then
    curl https://get.acme.sh | sh -s email=admin@${DUCKDNS_DOMAIN}
fi

export DuckDNS_Token="$DUCKDNS_TOKEN"

# Define Let's Encrypt como autoridade padrao (evita burocracia do ZeroSSL)
"$HOME/.acme.sh/acme.sh" --set-default-ca --server letsencrypt

# Emite o certificado via DNS-01 (sem abrir portas no roteador)
"$HOME/.acme.sh/acme.sh" --issue     --dns dns_duckdns     -d "$DUCKDNS_DOMAIN"     --keylength ec-256     --force

mkdir -p "$HOME/nexus-termux/certs"

# Faz backup do certificado autoassinado antigo na primeira vez
if [ -f "$HOME/nexus-termux/certs/server.crt" ] && [ ! -f "$HOME/nexus-termux/certs/server.crt.selfsigned.bak" ]; then
    cp "$HOME/nexus-termux/certs/server.crt" "$HOME/nexus-termux/certs/server.crt.selfsigned.bak"
    cp "$HOME/nexus-termux/certs/server.key" "$HOME/nexus-termux/certs/server.key.selfsigned.bak"
fi

# Instala o certificado oficial e configura o hook de reload do Nginx no Runit
"$HOME/.acme.sh/acme.sh" --install-cert -d "$DUCKDNS_DOMAIN" --ecc     --fullchain-file "$HOME/nexus-termux/certs/server.crt"     --key-file "$HOME/nexus-termux/certs/server.key"     --reloadcmd "sv restart nexus-nginx"

# Garante que o crond esteja ativo para renovacao automatica a cada 60 dias
sv-enable crond >/dev/null 2>&1 || crond >/dev/null 2>&1 || true

echo "    [OK] Certificado Let's Encrypt instalado com sucesso em ~/nexus-termux/certs/!"
REMOTE_EOF

echo "==> [3/4] Validando resposta HTTPS na porta 8445..."
sleep 2
curl -fsSL --resolve "${DUCKDNS_DOMAIN}:8445:${TERMUX_HOST}" "https://${DUCKDNS_DOMAIN}:8445/api/health"
echo ""
echo "==> [4/4] CONCLUIDO! Acesse no Redmi 13 Pro 5G:"
echo "    https://${DUCKDNS_DOMAIN}:8445"
```

# backend/app.py
def validate_and_normalize_note_content(note_type_raw, content_raw):
    note_type = (note_type_raw or "text").strip().lower()
    if note_type not in ("text", "checklist"):
        return None, None, "note_type must be 'text' or 'checklist'"

    if note_type == "text":
        if content_raw is None:
            return "text", "", None
        if isinstance(content_raw, (list, dict)):
            return "text", json.dumps(content_raw, ensure_ascii=False), None
        return "text", str(content_raw).strip(), None

    # note_type == 'checklist'
    parsed = json.loads(content_raw) if isinstance(content_raw, str) else content_raw
    if not isinstance(parsed, list):
        return None, None, "Checklist content must be a JSON array"
    normalized = [
        {"text": str(item.get("text", "")).strip(), "done": bool(item.get("done", False))}
        for item in parsed
        if isinstance(item, dict) and str(item.get("text", "")).strip()
    ]
    return "checklist", json.dumps(normalized, ensure_ascii=False), None

function getActiveTabId() {
  const activeSection = document.querySelector('.view-section.active');
  if (activeSection && activeSection.id) {
    return activeSection.id.replace(/^view-/, '');
  }
  return state.currentView || 'overview';
}

function handleFabClick(e) {
  if (e) e.stopPropagation();
  const activeTab = getActiveTabId();

  // Dashboard: Lançamento Rápido (janelas secundárias flutuantes)
  if (activeTab === 'overview') {
    const fabContainer = document.getElementById('fab-container');
    const speedDial = document.getElementById('fab-speed-dial');
    const isOpen = fabContainer.classList.toggle('open');
    if (speedDial) speedDial.setAttribute('aria-hidden', isOpen ? 'false' : 'true');
    return;
  }

  // Outras Abas: Lançamento Completo direto no modal da aba atual
  closeFabSpeedDial();
  if (activeTab === 'finance') {
    state.financeSubTab === 'recorrencias' ? openRecurringRuleModal() : openFinanceModal();
  } else if (activeTab === 'tasks') {
    openTaskModal();
  } else if (activeTab === 'ritmo') {
    openStartWorkoutModal();
  } else if (activeTab === 'goals') {
    openGoalModal();
  } else if (activeTab === 'ideas') {
    state.activeIdeasSubTab === 'notes' ? openNoteModal() : openIdeaModal();
  } else if (activeTab === 'sleep') {
    openSleepModal();
  } else if (activeTab === 'time') {
    openTaskModal();
  }
}

CREATE INDEX IF NOT EXISTS idx_workout_items_exercise ON workout_items(exercise_id);

CREATE TABLE IF NOT EXISTS workout_sets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id INTEGER NOT NULL REFERENCES workout_items(id) ON DELETE CASCADE,
    position INTEGER DEFAULT 0,
    reps INTEGER DEFAULT 0,
    load REAL DEFAULT 0,
    done INTEGER DEFAULT 0,
    rpe REAL,
    completed_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_workout_sets_item ON workout_sets(item_id);

CREATE TABLE IF NOT EXISTS body_metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER DEFAULT 1,
    weight REAL NOT NULL,
    notes TEXT DEFAULT '',
    recorded_at TEXT NOT NULL UNIQUE,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_body_metrics_date ON body_metrics(recorded_at);

CREATE TABLE IF NOT EXISTS evolution_photos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER DEFAULT 1,
    metric_id INTEGER REFERENCES body_metrics(id) ON DELETE SET NULL,
    photo_path TEXT NOT NULL,
    angle TEXT DEFAULT 'frontal',
    taken_at TEXT NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_evolution_photos_taken ON evolution_photos(taken_at);

CREATE TABLE IF NOT EXISTS schedules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER DEFAULT 1,
    routine_id INTEGER NOT NULL,
    routine_name TEXT NOT NULL,
    scheduled_at TEXT NOT NULL,
    status TEXT DEFAULT 'pendente',
    workout_id INTEGER REFERENCES workouts(id) ON DELETE SET NULL,
    notified_at TEXT
);

CREATE INDEX IF NOT EXISTS idx_schedules_scheduled ON schedules(scheduled_at);

CREATE TABLE IF NOT EXISTS push_subscriptions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    endpoint TEXT NOT NULL UNIQUE,
    p256dh TEXT NOT NULL,
    auth TEXT NOT NULL,
    user_agent TEXT DEFAULT '',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

-- ==================== SLEEP MODULE TABLE ====================
CREATE TABLE IF NOT EXISTS sleep_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER DEFAULT 1,
    sleep_date TEXT NOT NULL UNIQUE,
    bedtime TEXT NOT NULL,
    wake_time TEXT NOT NULL,
    duration_minutes INTEGER NOT NULL,
    quality_rating INTEGER DEFAULT 3 CHECK(quality_rating BETWEEN 1 AND 5),
    notes TEXT DEFAULT '',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_sleep_logs_date ON sleep_logs(sleep_date);
